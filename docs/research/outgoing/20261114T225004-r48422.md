# Operation r48422: 0x181 two-field message

## Result and remaining boundary

This operation is a complete ten-byte MapleStory client-to-server message. Its construction opcode is **0x181**, its observed wire opcode is **0xf68f**, and its two fields are the unsigned 32-bit values **2** and **21913** (`0x5599`).

The selected path reads the second value directly from object offset `0x124c`. That offset is the seed of a protected-integer structure, not an established object identifier. The object is selected using a type marker and a point/bounds check. The purpose of the report, the meaning of its fields, and any server-side use remain **unresolved**.

Thus the byte layout is fully decoded, but this is not a claim of full protocol-level understanding. No filter is recommended for this message yet.

## Object selection and transmitted field

The helper at `0x2a71320` traverses a linked structure. For each candidate it:

- obtains an object through the node and wrapper pointers;
- gets a small structure at `object + 0x1248`;
- requires its first 32-bit value to be nonzero and its value at `+8` to equal `2`;
- obtains a bounding rectangle through `object + 0x40`;
- requires the supplied point to lie within the rectangle's strict bounds.

This establishes **how** an object is selected. It does not name the object type or explain why the server needs the report.

The selected path sends the raw value at `object + 0x124c`. Surrounding code establishes a protected integer:

| Offset | Stored value |
|---|---|
| `+0x124c` | 32-bit seed, directly returned by `0x280b290` |
| `+0x1250` | Encoded value |
| `+0x1254` | Checksum supplied to the protected getter |

The writer at `0xcaf1e0` calls RNG routine `0x7ac850`, then stores the seed, encoded value, and checksum. The getter at `0x204350` computes `rol5(encoded) XOR seed` and compares the checksum. Some other callers test that decoded value as a boolean. None of those callers assigns a protocol meaning to the raw seed sent here.

Therefore, **the second field must not be described as an object ID, position, status code, or the decoded boolean**. It is specifically the raw seed in the selected path.

- observed second-field values range from `21790` (`0x551e`) to `33835` (`0x842b`).

These observations establish the supported layouts, not a universal constraint that other values or lengths are invalid.

The same outer function contains a different ten-byte path at `0x2978533..0x297859f`. It obtains a global/container object through `0x1924180`, calls `0x1923b30` with the point/rectangle structure, and sends that call's nonzero 32-bit return value after constant `2`. That path does **not** read `object + 0x124c`. The saved r48422 runtime caller identifies the object-field path, not this alternate producer.

The bounded decoder therefore uses neutral names `field_0x02` and `field_0x06`, and leaves `name` null. It accepts the observed six-byte form and the ten-byte form beginning with `2`; truncation, unexpected trailing bytes, and extra bytes after first field `3` remain partial with unresolved ranges.
